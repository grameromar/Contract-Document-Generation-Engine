En desarrollo

Capa web

Adaptador FastAPI que expone el core por HTTP. Tiene dos endpoints: POST /parse devuelve los campos de una plantilla y POST /generate devuelve el PDF.

rama
Nada de esta página está en main. La rama feature/backend/web tiene POST /parse. La rama feature/backend/web-generate-endpoint parte de ella y añade POST /generate y la configuración de Tectonic. Ninguna está fusionada en main; esta página describe la segunda.

Cómo verla

# leer un archivo sin cambiar de rama
git show feature/backend/web:backend/src/latexgen/web/routes.py

# o cambiar a la rama (con el árbol de trabajo limpio)
git switch feature/backend/web-generate-endpoint

# ver lo que añade la rama de /generate
git diff feature/backend/web feature/backend/web-generate-endpoint

La capa web solo traduce: no tiene lógica de negocio, y Pydantic queda fuera del core.

Flujo de una petición

POST /parse

Devuelve los campos de una plantilla para que el frontend construya el formulario. La plantilla viaja como texto dentro del JSON, no como archivo.

POST /parse
{"template": "{{cliente}} {{monto?:number}} {{pais:enum(MX,US)}} {{f:date(%d/%m/%Y)}}"}

200 OK
{"fields": [
  {"name": "cliente", "type": "string", "required": true,
   "options": [], "date_format": null},
  {"name": "monto", "type": "number", "required": false,
   "options": [], "date_format": null},
  {"name": "pais", "type": "enum", "required": true,
   "options": ["MX", "US"], "date_format": null},
  {"name": "f", "type": "date", "required": true,
   "options": [], "date_format": "%d/%m/%Y"}
]}
POST /parse
{"template": "{{x:color}}"}

422 Unprocessable Entity
{"detail": "Unsupported type 'color' for field 'x'. Valid types: boolean, date, enum, number, string."}
POST /parse
{}

Respuestas reales obtenidas del servidor de la rama con uvicorn. Con el encabezado Origin: http://localhost:5173, la respuesta trae access-control-allow-origin para ese origen.

Errores a HTTP

Los documentos inválidos del usuario dan 422; la falta del compilador, que es un problema del servidor, da 503.

Excepción del coreCódigoCuerpo JSON
ParseError422{"detail": str(exc)}
MissingFieldsError422{"detail": str(exc), "missing_fields": exc.missing_fields}
InvalidFieldValueError422{"detail": str(exc), "field": exc.field_name}
CompileError422{"detail": "LaTeX compilation failed.", "errors": exc.errors}
CompilerNotFoundError503{"detail": str(exc)}

/parse solo puede producir ParseError; /generate puede producir cualquiera. Un timeout de compilación también es CompileError. El log de CompileError no se envía al cliente.

Configuración

# backend/config/settings.yaml (en la rama)
cors_origins:
  - "http://localhost:5173"
  - "http://127.0.0.1:5173"

# LaTeX engine.
tectonic_path: "tectonic"
compile_timeout: 30.0
ClaveObligatoriaQué controla
cors_originssíOrígenes del frontend que pueden llamar a la API.
tectonic_pathno, "tectonic"Nombre del ejecutable (se busca en el PATH) o ruta completa.
compile_timeoutno, 30.0Segundos máximos por compilación; debe ser mayor que 0. Al agotarse, la compilación cuenta como fallida.

load_settings(path=None) busca el archivo en este orden: el argumento path, la variable de entorno LATEXGEN_CONFIG, y backend/config/settings.yaml resuelto desde la ubicación de config.py (no desde el directorio actual). Un YAML vacío o sin cors_origins falla al validar con Pydantic.

get_service() lee la configuración en su primera llamada y construye TectonicCompiler(tectonic_path, compile_timeout). Como el resultado queda en caché, un cambio en el YAML se aplica al reiniciar el servidor.

La configuración se lee al importar

Como main.py ejecuta app = create_app() a nivel de módulo, importar latexgen.web.main ya lee el YAML. Si el archivo no se encuentra, la importación falla.

Arrancar el servidor

Con la rama activa e instaladas sus dependencias (pip install -e ".[dev]" desde backend/):

uvicorn latexgen.web.main:app --reload

Probado con uvicorn latexgen.web.main:app --port 8765: arranca y responde. FastAPI sirve la documentación automática de la API en /docs.

POST /generate

Corre el pipeline completo (analiza, renderiza y compila) y devuelve el PDF como descarga. La plantilla viaja como texto en el JSON; el frontend la leerá del .tex con FileReader.

POST /generate
{"template": "...Hola {{nombre}}, renta \\${{renta:number}}...",
 "values": {"nombre": "Ana & Co", "renta": "12500.50"}}

200 OK
content-type: application/pdf
content-disposition: attachment; filename="document.pdf"
<bytes del PDF>

Respuesta real del servidor con uvicorn; el PDF dice "Hola Ana & Co, renta $12,500.5.". Sin el valor de renta, la misma petición da 422 con {"detail": "Missing required fields: renta", "missing_fields": ["renta"]}.

CampoTipoSignificado
templatestr, obligatorioTexto de la plantilla .tex.
valuesdict[str, str | int | float | bool | None], {} por defectoValor de cada campo por nombre. Las claves sin campo se ignoran; una lista u objeto como valor da 422.
  • Nombre del archivo: fijo, document.pdf; el frontend puede renombrar la descarga.
  • Números: un número JSON llega como int o float antes de que el core lo vea, y un float pierde los ceros a la derecha y la precisión que no quepa en él. Para conservar exactamente lo que escribió el usuario, el frontend debe mandar los números como texto ("1234.5000").
  • Concurrencia: la ruta es def, no async def. Compilar bloquea hasta compile_timeout segundos, y FastAPI ejecuta las funciones def en un hilo aparte, así que una compilación lenta no detiene las demás peticiones.
Decidido, sin implementar: idioma de las fechas

La petición tendrá un campo opcional para el idioma de los meses y días de date, con español por defecto. Requiere primero el cambio en el core.
