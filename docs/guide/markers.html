Marcadores y tipos

La gramática de los marcadores {{…}} y lo que hace cada tipo con el valor que recibe: qué acepta, cómo lo presenta y cuándo lo rechaza.

Gramática

Un marcador tiene la forma {{ nombre [?] [: tipo [(argumento)] ] }}. La define un único regex, compartido por el parser y el renderer markers.py:26:

MARKER_PATTERN = re.compile(
    r"\{\{\s*(\w+)\s*(\?)?\s*(?::\s*(\w+)\s*(?:\(([^)]*)\))?\s*)?\}\}"
)
GrupoParteQué hace el parser con él
1Nombre: \w+Identifica el campo. En Python, \w es Unicode: {{año}} es válido.
2? opcionalSi aparece, required=False. Si no, el campo es obligatorio.
3Tipo: \w+Se pasa a minúsculas (NUMBER vale como number). Ausente significa string. Fuera de VALID_TYPES es ParseError.
4Argumento: [^)]*En enum, lista de opciones separadas por comas. En date, el formato strftime. En los demás tipos se ignora.

Reglas del parser

  • Tipos válidos: string, number, date, boolean, enum parser.py:17.
  • Opciones de enum: se separan por comas, se les quitan los espacios de los extremos y se descartan las vacías. Un enum sin opciones (enum() o enum( , )) se convierte en un campo string.
  • Formato de date: se guarda sin espacios en los extremos. Si falta o queda vacío, date_format es None y se usará ISO (%Y-%m-%d).
  • Repeticiones: un campo puede aparecer varias veces si todas sus declaraciones son idénticas (tipo, obligatoriedad, opciones y formato). Cualquier diferencia es ParseError; por ejemplo {{x}} y {{x?}}, o {{d:date}} y {{d}}.
  • Lo que no cumple la gramática no es marcador: se queda como texto en el documento, sin error. Ejemplos: {{a-b}} (guion en el nombre), {{x:date(%d (x))}} (un ) dentro del argumento) y {{ x:enum(a)b }} (texto después del paréntesis).

Tipos y escape

El renderer pide a get_escaper una función por tipo escaping.py:263. Cada una valida, da formato y devuelve texto seguro para LaTeX; si el valor no sirve, lanza ValueError, que el renderer convierte en InvalidFieldValueError. Los campos opcionales vacíos nunca llegan al escaper: se sustituyen por "".

_escape_number escaping.py:111:

  1. Convierte el valor a texto, quita todas las comas y los espacios de los extremos.
  2. Exige ^-?\d+(\.\d+)?$: signo menos opcional, dígitos y, como mucho, una parte decimal. No admite +, notación científica ni varios puntos.
  3. Lo convierte a float. Si el texto tenía punto decimal, lo formatea como float con comas; si no, como entero con comas.

Límites observados (paso por float)

Como todo número pasa por float, con valores grandes o muy precisos la salida cambia. Comprobado con el código actual:

  • "12345678901234567890" da 12,345,678,901,234,567,168 (pierde precisión).
  • "123456789.123456789" da 123,456,789.12345679.
  • Con punto decimal, a partir de 1016 o por debajo de 0.0001 sale en notación científica: "99999999999999999.0" da 1e+17 y "0.00001" da 1e-05.

Ninguna prueba cubre estos casos; no está claro si son intencionales.

_make_date_escaper(date_format) escaping.py:144 fabrica un escaper con el formato capturado. El escaper:

  • Usa el valor tal cual si ya es un datetime.date.
  • Si no, lo convierte a texto, quita espacios y llama a date.fromisoformat. Es lo que produce un <input type="date"> de HTML: AAAA-MM-DD. Con Python 3.11 (el del entorno) también acepta otras formas ISO 8601, como 20240115 o 2024-W03-1; 2024-1-5 no.
  • Rechaza fechas imposibles: 2023-02-29 es ValueError.
  • Devuelve parsed.strftime(date_format).
Los nombres de meses y días dependen del locale

Directivas como %B o %A siguen el locale del proceso, y el código no lo configura. En este equipo, {{f:date(%d de %B de %Y)}} con 2024-01-05 produce 05 de January de 2024.

La salida de strftime no se escapa. El formato lo escribe el autor de la plantilla, no el usuario que llena el formulario.

_escape_boolean escaping.py:190 devuelve Sí o No, textos fijos que no necesitan escape. Un bool de Python se traduce directo; cualquier otro valor se convierte a texto, sin espacios y en minúsculas, y se busca en dos conjuntos:

ResultadoTextos aceptados
Sítrue, 1, yes, y, si, sí, on, verdadero
Nofalse, 0, no, n, off, falso, cadena vacía

Todo lo demás es ValueError, para que una errata no termine en un "No" silencioso. La cadena vacía figura entre los falsos, pero desde el renderer nunca llega: un valor vacío cuenta como "no proporcionado".

_make_enum_escaper(options) escaping.py:218 acepta solo valores idénticos a una opción: distingue mayúsculas y no recorta espacios del valor (las opciones sí se recortaron al parsear). El valor aceptado se escapa como texto, porque una opción puede contener caracteres especiales.

{{pais:enum(México,USA,Canadá)}}
# "USA"  → USA
# "usa"  → ValueError: Value 'usa' is not among the allowed options: ['México', 'USA', 'Canadá']
