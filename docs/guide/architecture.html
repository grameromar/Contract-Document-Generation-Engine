Visión general

Arquitectura

Arquitectura en capas: un core de dominio sin dependencias de terceros, rodeado de adaptadores que lo exponen. Hoy solo el core está en main.

Capas

La regla que sostiene el diseño: el core no depende de ningún framework. En main, pyproject.toml declara dependencies = [] y los módulos del core solo importan de la biblioteca estándar (re, datetime, typing, dataclasses, abc, subprocess, tempfile, pathlib). Tectonic no se importa: se ejecuta como proceso aparte. Así el mismo core podría servir a una API web o a una aplicación de escritorio sin cambios; los docstrings de models.py y service.py mencionan ambas como capas de entrega previstas.

Patrones de diseño

Factory

get_escaper(field_type, *, options, date_format) devuelve la función de escape adecuada para cada tipo. Las de date y enum se fabrican al vuelo con su configuración capturada en un cierre, así todas tienen la misma firma (value) -> str.

escaping.py:263

Strategy

Compiler es una clase abstracta con un método compile(tex_source). TectonicCompiler es la única implementación; las pruebas usan otras (stubs) sin tocar el service.

Service / Facade

TemplateService es el único punto de entrada que necesita una capa externa: parse y generate esconden las tres etapas.
